# 测试与证据边界

## 推荐入口

在 64 位 Windows PowerShell 5.1 中，从仓库根目录运行：

```powershell
.\scripts\Build.ps1
.\scripts\Test.ps1
```

Node 测试也可以单独运行：

```powershell
npm test
```

PowerShell 隔离测试文件位于 `tests\`，包括安装事务、hosts 字节级计划、helper
入口、状态判定和 lifecycle 清理 fixture。安装事务 fixture 还验证失败时不留下
任务/服务注册，以及 Unicode ownerName 和 `ProxyPort` 能保存在 UTF-8 settings
中。单独运行时使用 `powershell.exe -NoProfile -NonInteractive -File <test-file>`，
不要把测试脚本改成指向真实的系统 hosts。

## 覆盖内容

- relay 只接受 loopback 配置，限制连接数、握手头和预握手缓存，并正确转发
  HTTP `CONNECT` 成功/失败及 TLS 字节。
- 代理不可用、恢复、上游中断、停止请求和受保护 shutdown barrier 的状态转移。
- 可配置 `ProxyPort` 同时用于 TLS preflight 和 relay 上游连接。
- 安装事务的阶段性复制、失败保留受保护结果、Unicode settings 和已验证 payload
  参数。
- 卸载清理失败保留服务与任务注册，成功后再移除服务及安装目录。
- 日志轮转、大小上限和只暴露错误代码的写入失败状态。
- hosts 精确行的追加/移除、冲突/损坏拒绝、原始字节和 ACL/备份路径的保留。
- helper 对监听地址、进程所有者、Node/script 路径和严格命令行的身份检查；
  父启动器的路径、固定参数、所有者和启动时间也参与校验与写后复验。
- lifecycle 在 Stop、Initialize、owner logoff、其他会话、错误身份和 helper
  失败时的清理屏障。
- 普通用户隐藏窗口的实际定向 Windows 消息测试：查询、取消、确认结束、重复
  通知、超时、错误记录和不相关监听地址；不广播消息，不触发系统关机。
- PowerShell 5.1 重复替换清理回执；较新的失败/未完成记录不能被旧成功记录覆盖。
- 托盘启动的实际 PowerShell 子进程没有控制台窗口；退出清理成功且启动器已结束才
  允许退出；失败后可以重试。不同运行、旧版和缺失回执不能误报最近退出已确认。
- 创建实际菜单窗口后检查 Per-Monitor V2 上下文；本机 125% 缩放下的独立菜单
  绘制预览已检查文字与布局。不同缩放显示器之间动态切换仍未实机验证。

## 不要从测试推断的结论

隔离测试没有证明真实机器上的网络策略、代理实现、用户权限、第三方 DNS 缓存、
Codex 应用协议或业务送达。作者机器已验证前身的 service `STOP` 路径；前一版
PowerShell 内的退出窗口曾通过定向消息测试，但真实快速启动后没有新的成功回执。
因此托盘版改由 GUI 宿主持有退出窗口，并将回执绑定到每次运行。

托盘版已在既有安装上验证：登录触发、权限及任务设置保留，托盘/PowerShell/Node
没有控制台窗口；定向取消通知后继续运行；普通用户通过控制入口停止约 10 秒后，
整个进程链、监听和自有映射均消失，随后恢复到 ready，原生云端会话只读访问成功。
PowerShell 可能保留无窗口控制台对象，不能将其误判为用户看到的终端窗口。
上述自动化验收不是实际点击托盘菜单或真实关机测试；菜单共用的退出判定另有隔离测试。
随后一次用户实际使用记录中，关机前的 `tray_exit` 约 6.47 秒完成，进程、监听与映射
全部退出；下次快速启动后自动恢复，并正确关联这次回执。这验证了先退出托盘再关机的流程。

全新安装尚未在干净虚拟机实测，未手动退出托盘时的自动关机清理、断电和多用户竞态仍待验收。
自动化窗口消息测试不能代替这些场景。TLS 探测通过也不代表 WebSocket 已认证或
消息已经送达。

测试输出和诊断文件可能包含连接元数据、进程 ID、时间、路径或本地配置。公开报告
只保留脱敏的测试命令、版本、失败阶段和高层 reason；不要上传原始日志、settings、
hosts 备份或完整状态 JSON。
